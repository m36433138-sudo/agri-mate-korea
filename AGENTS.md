# Architecture rules
- Diagram detail and order dialogs share cart controls and paginated inventory lookup, matching exact/alternate codes and hyphen-delimited suffixes so checked-part locations stay consistent with individual lookup.
- Diagram catalogue thumbnails use pre-generated JPEGs at thumbs/<image_path> in the diagram bucket, signed in parallel 500-path chunks, and the list renders cards in 60-card scroll increments so thousands of diagrams stay responsive on phones; diagrams without a thumb fall back to client-side cropping. Source images and hotspot coordinates stay unchanged for part lookup.
- A parts book shared by several models keeps one combined model_name, and modelsOf (SHARED_BOOKS) maps it to every model button so model filters show it under each model without duplicating diagrams.
- Diagram list tabs (이앙기/콤바인/트랙터/부속장치) come from categoryOf: model-name prefix first, then machine_type, so imported books land in the right tab without a schema change.
- Error-code records retain independent photo paths in a private bucket; batch creation uploads before one atomic insert and cleans up on failure so records can be deleted independently.
- Machine lists fetch stable range-based pages before filtering so records beyond the Data API row cap remain discoverable.
- Global search uses a paginated SECURITY INVOKER RPC with normalized indexed fields and abortable query-keyed requests so RLS remains authoritative and stale responses cannot replace current results.- PDF diagram import runs in the browser (pdfjs text layer → part-number hotspots); label-photo linking reads codes server-side via the read-part-label function and only links after a staff pick, so AI never writes data directly.
- The operations board (작업현황판) reads and writes operation_rows as the source of truth; Google Sheets is a best-effort backup mirror and is imported only on first load or by the admin 「시트 가져오기」 button, so sheet outages never block work.
- Saving a repair with an unpaid/partial payment creates a finance_records receivable (source_type repair) in the same flow so billing never depends on staff remembering a second step.
- Receipts/invoices are read by the read-receipt function (staff with manage_expenses only) and land in a review dialog; rows are inserted into expenses only after the user confirms, with the original kept in the private receipts bucket.
- Photo part finding (find-part-by-photo) narrows by figure titles first, then compares only the top figures with their parts lists, and drops any AI-returned code not in that figure so suggestions can never point to nonexistent parts.
- The onsite-repairs page reads and writes the Google Sheets 출장 tab by header names, and edits merge into the existing row so sheet-only columns (priority, request date, completion date) are never blanked.
- The google-sheets function resolves every tab name (read, write, clock-in/out, inventory and customer sync) against the spreadsheet's real tab titles, ignoring spaces, and fails with the list of existing tabs, so a renamed or space-padded tab never produces a raw range error.
- The error-code page reads the manual from error_code_catalog (admin-editable, staff-readable) and links technicians' repair_error_codes by normalized code keys (spacing/dot/FMI ** wildcard) in src/lib/errorCodes.ts, so free-typed codes still find their manual entry without a foreign key.
- Insurance repair estimates live in insurance_estimate_items (separate from consumer quotes) and are saved through the replace_insurance_estimate_items SECURITY INVOKER RPC so the whole list swaps atomically under RLS; diagram picks reuse DiagramViewer via onPickParts, and repair input/edit dialogs reuse the same full-screen EstimateDiagramPicker (target label; model chip first, auto-picked from the machine via machineModelChip, then thumbnail cards) merging picks into part rows via src/lib/repairDiagramParts.ts.
- New Yanmar parts get their sales price from yanmar_supply_prices (VAT-excluded list with effective date) through src/lib/partPricing.ts, but an existing other-branch price wins because the inventory price-sync trigger would otherwise overwrite that branch's manually kept price.
- Drawing callouts auto-linked by the free local OCR job (table ref column → drawing number) carry notes='ocr-auto', so they can be reviewed or rolled back as one set without touching hand-made hotspots.
- Counter part sales live in part_sales/part_sale_items and are saved only through the create_part_sale SECURITY INVOKER RPC (sale, items, receivable in one transaction); an item trigger deducts/restores branch inventory with an inventory_adjustments log, and delete_part_sale removes the linked parts receivable, so stock and receivables never drift from the sale record.
- has_permission matches employee_permissions.employee_id against the auth user id (with an employees.id fallback) because the permission editor stores user ids there.
