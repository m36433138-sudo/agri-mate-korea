# Architecture rules
- Diagram detail and order dialogs share cart controls and paginated inventory lookup, matching exact/alternate codes and hyphen-delimited suffixes so checked-part locations stay consistent with individual lookup.
- Diagram catalogue thumbnails use pre-generated JPEGs at thumbs/<image_path> in the diagram bucket, signed in parallel 500-path chunks, and the list renders cards in 60-card scroll increments so thousands of diagrams stay responsive on phones; diagrams without a thumb fall back to client-side cropping. Source images and hotspot coordinates stay unchanged for part lookup.
- A parts book shared by several models keeps one combined model_name, and modelsOf (SHARED_BOOKS) maps it to every model button so model filters show it under each model without duplicating diagrams.
- Diagram list tabs (이앙기/콤바인/트랙터/부속장치) come from categoryOf: model-name prefix first, then machine_type, so imported books land in the right tab without a schema change.
- Error-code records retain independent photo paths in a private bucket; batch creation uploads before one atomic insert and cleans up on failure so records can be deleted independently.
- Machine lists fetch stable range-based pages before filtering so records beyond the Data API row cap remain discoverable.
- Global search uses a paginated SECURITY INVOKER RPC with normalized indexed fields and abortable query-keyed requests so RLS remains authoritative and stale responses cannot replace current results.- PDF diagram import runs in the browser (pdfjs text layer → part-number hotspots); label-photo linking reads codes server-side via the read-part-label function and only links after a staff pick, so AI never writes data directly.
- The operations board (작업현황판) reads and writes operation_rows as the source of truth; Google Sheets is a best-effort backup mirror and is imported only on first load or by the admin 「시트 가져오기」 button, so sheet outages never block work.
- Saving a repair with an unpaid/partial payment creates a finance_records receivable (source_type repair) in the same flow so billing never depends on staff remembering a second step.
- Receipts/invoices are read by the read-receipt function (staff with manage_expenses only) and land in a review dialog; rows are inserted into expenses only after the user confirms, with the original kept in the private receipts bucket.
- Photo part finding (find-part-by-photo) narrows by figure titles first, then compares only the top figures with their parts lists, and drops any AI-returned code not in that figure so suggestions can never point to nonexistent parts.
- Onsite repairs (방문수리) live in onsite_visits (RLS: view_onsite reads, manage_onsite writes) as the source of truth; the Google Sheets 출장 tab is a best-effort backup located by header names (sheet 분류 splits into status + category, unknown columns kept via sheet_raw, rows re-found by name+phone if shifted) and is imported only when the table is empty or by the admin 「시트 가져오기」. Addresses are geocoded once in the browser (Nominatim, widening to 읍·면, cached with geocoded_address; staff can move a pin on the map), and 「오늘」/map views number stops nearest-first from the user's location or branch office.
- The google-sheets function resolves every tab name (read, write, clock-in/out, inventory and customer sync) against the spreadsheet's real tab titles, ignoring spaces, and fails with the list of existing tabs, so a renamed or space-padded tab never produces a raw range error.
- The error-code page reads the manual from error_code_catalog (admin-editable, staff-readable) and links technicians' repair_error_codes by normalized code keys (spacing/dot/FMI ** wildcard) in src/lib/errorCodes.ts, so free-typed codes still find their manual entry without a foreign key.
- Insurance repair estimates live in insurance_estimate_items (separate from consumer quotes) and are saved through the replace_insurance_estimate_items SECURITY INVOKER RPC so the whole list swaps atomically under RLS; diagram picks reuse DiagramViewer via onPickParts, and repair input/edit dialogs reuse the same full-screen EstimateDiagramPicker (target label; model chip first, auto-picked from the machine via machineModelChip, then thumbnail cards) merging picks into part rows via src/lib/repairDiagramParts.ts.
- Part prices for new Yanmar parts and for estimate/repair lines resolve through src/lib/partPricing.ts: inventory sales price first, else yanmar_supply_prices (VAT-excluded list with effective date); for new registrations an existing other-branch price wins because the inventory price-sync trigger would otherwise overwrite that branch's manually kept price.
- Callout hotspots made by OCR (offline job or in-browser src/lib/calloutOcr.ts during PDF import / 「번호 자동 찾기」) only use numbers in that page's table and carry notes='ocr-auto', so 「자동 표시 지우기」 or a rollback removes exactly that set; model names compare via canonicalModelName so spelling variants share one model button.
- Counter part sales live in part_sales/part_sale_items and are saved only through the create_part_sale SECURITY INVOKER RPC (sale, items, receivable in one transaction); an item trigger deducts/restores branch inventory with an inventory_adjustments log, and delete_part_sale removes the linked parts receivable, so stock and receivables never drift from the sale record.
- has_permission matches employee_permissions.employee_id against the auth user id (with an employees.id fallback) because the permission editor stores user ids there.
- Deposit SMS land in bank_deposits (deposit-sms function or paste) via the shared parser _shared/depositSms.ts; depositMatch.ts only suggests, money moves only through approve_bank_deposit (revert_bank_deposit undoes it), and every inbound request is logged in deposit_sms_inbox (30-day prune) for 「연결 시험」 diagnosis.
- Repair input/edit and insurance repair dialogs are full-screen on phones (formDialogContentClass), ignore outside taps, and close or save only from FormDialogTopBar; useUnsavedGuard compares a snapshot taken after the form resets (and after existing rows load) and asks before discarding edits. A chosen customer shows as SelectedCustomerCard and search opens only via 「고객 변경」, with dialog auto-focus disabled so the keyboard never pops on open.
- Navigation is defined once in src/components/nav/navItems.ts (permission-filtered; sidebar groups remember state, phones get BottomTabBar). Dashboard numbers come only from real data (src/lib/repairTrend.ts compares the same days of last month); the AI card only pre-fills /chat?q=.
- List pages share src/components/page/PageParts.tsx (PageHeader, SearchField, Segmented, ShowMore): wide screens get a table, phones/tablets get cards, rows render in 100-item increments, and row actions (delete, edit, etc.) sit in a ⋯ menu so they are reachable on touch screens. Status/branch/machine-type badges use theme-aware translucent colors (bg-*-500/15 with dark: text variants) so they read in both light and dark mode.
- Parts receiving: Yanmar statement PDFs are read without AI by src/lib/yanmarStatement.ts, other receipts by read-receipt; saving creates an expense plus a part_receipts 「입고 대기」, and stock changes only via the receive_part_receipt SECURITY INVOKER RPC (lines never counted twice). Shelf photos live in inventory_location_photos.
- Counter part sale 거래명세서 print through PartSalePrintDialog → src/lib/printPartSale.ts in the same YANMAR style as the estimate (shared CompanyPicker remembered per branch, seal on (인), amount in Korean words, VAT split, 청구/영수 by remaining balance, optional 공급자 보관용 second page) via the hidden-iframe printHtmlDocument, so popup blockers never stop printing.
- The insurance estimate prints through EstimatePrintDialog: staff pick the issuing business from companies (last choice remembered), the page shows 대표 (인) with the uploaded stamp_url seal (a white-stripped PNG data URL set in 사업자 관리), amount in Korean words and a VAT split, and optional landscape diagram pages built by src/lib/estimateDiagrams.ts that highlight each diagram-picked part with its estimate line number. Its parts legend can add 장흥/강진 location·qty columns (loadPartLocations: exact code, then alt code; toggle remembered). DiagramViewer with onPickParts offers 「페이지 통째로 담기」 for every part on the page.
- AI-calling edge functions map gateway failures through supabase/functions/_shared/aiError.ts (402/429/403 → Korean staff messages, cause chain searched because streamText hides the status) and screens read the body via src/lib/functionError.ts, so credit shortages never show as a generic read failure.
- Clock in/out from the dashboard (AttendanceCard via src/hooks/useMyAttendance.ts) writes the logged-in employee's own attendance_records row and a technician_locations point; while clocked in and the app is open, useLiveLocationRunner (mounted once in Layout) upserts staff_live_locations (own row only by RLS, throttled to 1 min/100 m, stopped on clock-out or toggle) shown in LiveStaffPanel and the onsite map. Browsers cannot track a closed or locked app.
- Quote products are a catalog grouped by machine_group (src/lib/productCatalog.ts MACHINE_GROUPS) with photos in the public product-images bucket (resized to 1600px on upload); ProductGrid/ProductDetail serve both the catalog page and the quote product picker, and QuotePrintView shows photos and highlights of the chosen products. Stock Yanmar product photos ship with the app under public/products/*.jpg and are stored as image_path "/products/…" (productImageUrl returns them as same-origin URLs; isBucketImage keeps replace/delete from touching the bucket for them); a unit_price of 0 shows as 「가격 미정」 via productPrice.
- The app is an installable PWA (public/manifest.webmanifest, public/sw.js registered only in production builds outside iframes; navigation is never cached, offline shows a notice). Push uses Web Push implemented with WebCrypto in supabase/functions/_shared/webpush.ts (aes128gcm + VAPID); the private JWK lives only in vault (push_vapid_private(), service_role only), subscriptions register through register_push_subscription per device with topics, and send-push (staff-only) resolves recipients server-side (employee names, chat room members, admins, self) so the client never reads other employees' accounts.
- Customer and machine records are shared company-wide: every staff member (is_staff) can read all customers and machines regardless of branch, and view_customers/view_machines are always granted to employees (STAFF_SHARED_PERMISSIONS in src/lib/permissions.ts, shown locked in the permission editor). Creating/editing customers still needs edit_customers, deleting stays admin-only, and customer accounts only see their own customer row, machines and repairs.
- 외출 (stepping out while clocked in) lives in attendance_breaks (one open break per employee, own rows or admin by RLS, no location recorded): while out, useLiveLocationRunner stops and staff_live_locations.sharing goes false; clock-out closes an open break, and calcOvertimeWithBreaks (src/hooks/useAttendance.ts) subtracts break time from worked time, the 8-hour threshold and the morning/evening overtime windows, storing the day total in attendance_records.break_minutes.
- Assignees are employee names: pickers use StaffPicker (src/components/StaffPicker.tsx) over the staff_directory() SECURITY DEFINER RPC (active employees incl. linked admins, names/teams only, staff-only) because employees RLS hides other employees; multi-person fields store "김영일, 마성수" and are matched by exact name tokens (splitNames/isMine). quotes.assignee and finance_records.assignee join technician fields (operation_rows, onsite_visits, insurance_repairs) in 내 업무 「내 담당」 (MyAssignedWork), assignees of a quote can read and edit it through RLS (my_employee_name()), and newly assigned people get a push via notifyAssignees.
- Login persistence goes through src/lib/authStorage.ts: auto-login (key agrimate-auto-login-v2, on by default; the old "false" key is ignored) keeps the Supabase session in localStorage, off uses sessionStorage, reads migrate a session found in the other store, and the last login ID is prefilled on the login screen.
- Repair registration (RepairInputModal) records error codes through ErrorCodePicker (src/components/errorCodes/ErrorCodePicker.tsx): search the cached error_code_catalog (same query key as the error-code page) by code fragment or symptom, ranked by machineFitScore for the chosen machine's model, or add a typed code via parseErrorCodes; codes are inserted into repair_error_codes after the repair (symptom from the manual part, action from the repair content, resolved flag), and a failure there only warns because the repair is already saved.
- 천년경영 거래 원장 import (admin, 고객관리 ⋯ menu → MjLedgerImportDialog) parses 「거래처 원장」 xls in the browser with src/lib/mjLedger.ts (header columns by name, 합계 rows and the 사업자번호/주민번호 column never read). Each file belongs to a book (MJ_BOOKS: 구천년 장흥 old-jh / 구천년 강진 old-gj, both cut at 2025-10-31, and the merged 신천년 new; guessMjBook pre-selects, staff can change); codes and slip numbers are per book, so source_key and customer links are book-prefixed (customer_legacy_codes (book, code) → customer; people in several books are grouped into one new customer by phone). Overlapping exports of one book: the later-ending file wins (mergeMjExports) and import deletes that period per customer code before inserting, so edits/deletes in 천년경영 never leave stale lines. ledger_entries/customer_legacy_codes RLS: staff read, admin write.
- The customer 거래 원장 card (CustomerLedgerCard via src/lib/customerLedger.ts) merges ledger_entries with app repairs and part_sales dated after the latest imported entry_date, pages by year ◀▶ and month chips, and prints selected days as a statement. Balances start from each account's first 전기이월 (old books' carries; the 신천년 first carry is old balance moved over and is dropped when old history exists), and carryAdjustments adds display-only 「이월 조정」 lines (a later carry differing from the running balance; 2025-11-01 신천년 이월 vs 구천년 10/31 balance) so the current balance always equals 신천년's; customers with 구천년 history but no 신천년 account get a 「구천년 잔액 정리」 line zeroing their 10/31 balance, because 미수 is defined by 신천년 only.
- Statements share one renderer: statementHtml(StatementDoc) in src/lib/printPartSale.ts and StatementPrintDialog (part sales, repairs via src/lib/repairStatement.ts from the repairs ⋯ menu or 「저장하고 바로 거래명세서 인쇄」, and the ledger). 무상(서비스) repairs store total_cost 0 with is_free_service, free_reason and waived_amount (the original amount), create no receivable, still deduct parts, and print the waived amount and reason.
- Customers are merged only through the merge_customers(src, dst) SECURITY DEFINER function (admin or server only): it repoints every customer reference (ledger, legacy codes, machines, sales history, repairs, receivables, quotes…), fills dst's empty fields, logs the deleted src row and moved counts in customer_merge_log (admin-readable) for undo, then deletes src. 천년경영 「판매자+중고+기계(모델)-구매자」 accounts were cleaned by creating a 중고기계 machine (serial 「미확인-…」) owned by the buyer with trade_in/sale rows in machine_sales_history and merging the account into the buyer.
- 빼놓은 부품 (부품관리 「빼놓은 부품」 tab) lives in part_holds/part_hold_items (staff read/write, delete by creator or admin): who it is for (customer and/or StaffPicker assignee), purpose, a spot memo and up to 6 photos in the part-photos bucket under holds/; held → 사용함/다시 넣음. Holds never change inventory (repairs and part sales deduct it); 부품현황 only shows 「빼놓음 N」 via heldQtyByCode.
- 창고 이동 (부품관리 「창고 이동」 tab) moves stock between the 장흥/강진 warehouses only through the transfer_parts SECURITY INVOKER RPC: one transaction locks the source row, refuses the whole transfer if any line exceeds source stock, adds to (or creates, copying name/prices) the destination row with an optional new location, logs both sides in inventory_adjustments and records part_transfers/part_transfer_items (staff read/insert only, no update/delete, so history stays fixed).
- The Android app (android/, Capacitor, appId com.gwangmun.cs) only wraps https://cs.gwangmun.com, so web deploys update it without reinstalling; rebuild the APK (public/app/gwangmun.apk, linked from 앱·알림 설정) only for native changes. In it, useLiveLocationRunner uses @capacitor-community/background-geolocation (foreground-service notification, useLegacyBridge) via src/lib/nativeLocation.ts and saves staff_live_locations through CapacitorHttp so sharing keeps going with the screen off; the signing key stays outside git (android/keystore.properties).
